## 1. Цель

Проверить, что основные пользовательские сценарии интернет-магазина (авторизация → выбор товара → корзина → оформление заказа) и CRUD-операции API бронирования работают корректно, а дефекты задокументированы и классифицированы по критичности.

## 3. Скоуп

### В скоупе
| Модуль | Виды тестирования |
|---|---|
| Login | Функциональное, негативное, безопасность (базово) |
| Products (каталог, сортировка, карточка) | Функциональное, UI |
| Cart | Функциональное |
| Checkout (Information → Overview → Complete) | Функциональное, негативное, валидация полей |
| Burger-меню, Footer | Функциональное |
| Кроссбраузерность | Chrome, Firefox, Edge |
| Адаптивность | 1920×1080, 1366×768, 768×1024, 375×812 |
| API /auth, /booking, /ping | Функциональное, негативное, статус-коды, схема ответа |

### Вне скоупа
- Нагрузочное тестирование (за исключением фиксации заметных задержек)
- Тестирование безопасности за пределами базовых проверок
- Реальная оплата (в приложении её нет)
- Автоматизация UI

## 4. Подход

1. Анализ требований (их нет в явном виде → используются эвристики, здравый смысл и поведение `standard_user` как эталона).
2. Тест-дизайн (см. [test-design.md](test-design.md)).
3. Smoke-тестирование под `standard_user`.
4. Прогон чек-листа и тест-кейсов.
5. Исследовательское тестирование (exploratory) под проблемными пользователями - сессии по 30 минут.
6. Заведение дефектов, ретест.
7. Итоговый отчёт.

## 6. Критерии

**Критерии начала:** приложения доступны, тестовые данные известны, тест-кейсы готовы.

**Критерии окончания:**
- выполнено 100% тест-кейсов с приоритетом High;
- выполнено ≥ 90% всех тест-кейсов;
- все найденные дефекты заведены и классифицированы;
- нет открытых Blocker-дефектов на `standard_user`.

## 7. Классификация дефектов

| Severity | Описание |
|---|---|
| Blocker | Блокирует ключевую функциональность, обходного пути нет |
| Critical | Ломает ключевой сценарий (покупка, авторизация) |
| Major | Существенно нарушает работу функции, есть обходной путь |
| Minor | Незначительное отклонение, не мешает основному сценарию |
| Trivial | Косметика, опечатки |

Priority (High / Medium / Low) выставляется отдельно - по срочности исправления для бизнеса.
